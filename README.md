# Wheat Disease Classifier

A ResNet50-based Python library and CLI for classifying wheat leaf images
into five disease categories.

![CI](https://github.com/Alikhan2215/wheat-disease-classifier/actions/workflows/ci.yml/badge.svg)

---

## Scientific context

This module is the inference core of a master's research project:
**"Wheat disease dataset expansion using GAN and diffusion models"**.

The research investigates how synthetic images generated by Generative
Adversarial Networks (GANs) and diffusion models can augment limited
real-world datasets to improve deep-learning-based wheat disease diagnosis.
This classifier accepts a single wheat leaf photograph and returns one of
five diagnoses.

| Class | Description |
|---|---|
| **BlackPoint** | Fungal grain discolouration at the tip |
| **FusariumFootRot** | Crown and foot rot caused by *Fusarium* spp. |
| **HealthyLeaf** | No disease present |
| **LeafBlight** | Necrotic lesions on leaf blades |
| **WheatBlast** | Spike bleaching caused by *Magnaporthe* spp. |

## Installation

**Prerequisites:** Python 3.11, pip.

```bash
git clone https://github.com/Alikhan2215/wheat-disease-classifier.git
cd wheat-disease-classifier
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Usage

```bash
# Demo mode — random weights, no .pth file required
python -m wheat_classifier.cli leaf.jpg

# With fine-tuned weights
python -m wheat_classifier.cli leaf.jpg --model path/to/weights.pth
```

### Library API

```python
from wheat_classifier import build_model, predict

model = build_model(pretrained=False)       # or load_model("weights.pth")
result = predict("leaf.jpg", model=model)

print(result["class"])          # e.g. "LeafBlight"
print(result["confidence"])     # e.g. 0.734
print(result["probabilities"])  # {"BlackPoint": 0.042, ...}
```

## Technology justification

| Technology | Justification                                                                                                                                                                                                                   |
|---|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Python 3.11** | Standard for ML engineering; extensive library ecosystem; clear syntax reduces maintenance overhead; version 3.11 adds meaningful runtime performance improvements.                                                             |
| **PyTorch / torchvision** | The leading deep-learning research framework; dynamic computation graph simplifies debugging; torchvision's pretrained model zoo makes loading a ResNet50 backbone a two-line operation.                                        |
| **ResNet50** | Residual skip-connections solve the vanishing-gradient problem in deep CNNs; ResNet50 achieves a strong accuracy/speed trade-off and is the standard backbone for transfer learning in plant-disease classification literature. |
| **Pillow** | Canonical Python imaging library required by torchvision transforms; provides `ImageOps.exif_transpose()`, which silently corrects phone-camera orientation bugs that would degrade prediction accuracy.                        |
| **NumPy** | Required by Pillow and PyTorch data utilities; zero extra overhead as it is already a transitive dependency.                                                                                                                    |
| **pytest** | Fixture-based testing removes boilerplate; the built-in `tmp_path` fixture provides isolated per-test directories for synthetic images; failures produce clear diffs that accelerate debugging.                                 |
| **GitHub Actions** | Native to GitHub and free for open-source repositories; YAML configuration is version-controlled alongside the source; built-in actions for checkout and Python setup keep the workflow concise.                                |

## Testing

All tests run fully offline - no GPU, no `.pth` file, no network access required.

```bash
pytest -v
```

| Test module | Coverage |
|---|---|
| `tests/test_model.py` | `NUM_CLASSES`, `CLASS_NAMES` values, output tensor shape `(1, 5)`, offline build |
| `tests/test_preprocess.py` | Tensor shape `(1, 3, 224, 224)`, dtype `float32`, ImageNet normalisation confirmed |
| `tests/test_predict.py` | Return-dict keys, class validity, confidence in `[0, 1]`, probabilities sum to `1.0` |

Run the linter separately:

```bash
flake8 wheat_classifier tests
```

## CI/CD

The GitHub Actions workflow (`.github/workflows/ci.yml`) runs in two stages:

1. **Continuous integration (`test` job).** On every push and pull request,
   the code is linted with `flake8` and the full `pytest` suite is run on
   Python 3.11.
2. **Continuous delivery (`build` job).** On push to `main`, and only after
   the `test` job passes, the package is built with `python -m build` and the
   resulting wheel and source distribution from `dist/` are uploaded as a
   workflow artifact, ready to download or publish.

## Limitations

- **Demo mode** (no `--model` flag) uses a randomly initialised ResNet50.
  Predictions are meaningless without a fine-tuned weights file.
- The five classes cover a subset of wheat pathogens; novel diseases will
  be misclassified as one of the known categories.
- Accuracy depends on the quality and diversity of the training data;
  out-of-distribution images may produce unreliable results.
- Confidence scores are not calibrated probabilities.
- **This tool is not a certified diagnostic instrument.** Always consult a
  qualified agronomist or plant pathologist before taking any crop-management
  or treatment decision.

## Conclusion and challenges

Developing this as a well-structured Python package - rather than a research
notebook - surfaced several practical engineering challenges:

1. **Offline CI.** PyTorch's `resnet50(pretrained=True)` downloads ~100 MB
   on first call, which fails in CI environments without network access. The
   `pretrained: bool` flag defaulting to `False` allows tests to build the
   model from random weights in under one second.

2. **EXIF orientation.** Smartphone images embed rotation metadata that PIL
   silently ignores without an explicit `ImageOps.exif_transpose()` call,
   causing wrong predictions for portrait-mode photos. This was discovered
   during manual testing and added to the preprocessing pipeline.

3. **Type-hint compatibility.** Python 3.10+ union syntax (`X | Y`) is
   cleaner than `Optional[X]` from `typing`, but requires a known minimum
   Python version. Pinning `requires-python = ">=3.11"` in `pyproject.toml`
   resolves this project-wide.

4. **Packaging vs. notebooks.** Structuring code as an installable package
   with a proper `__init__.py`, `pyproject.toml`, and `pythonpath` config
   avoids the `sys.path` hacks common in research notebooks and makes the
   module straightforwardly importable by other projects.
